# Вариант 15: визуализация графа зависимостей

CLI-приложение для изучения зависимостей Rust-пакетов Cargo. Решение
развивается по пяти этапам из задания. Для получения зависимостей исходные
манифесты и метаданные читаются напрямую; Cargo и сторонние библиотеки не
используются как источник графа.

## Требования

- Python 3.11 или новее;
- Git для загрузки удалённого репозитория в обычном режиме.

Внешние Python-пакеты не нужны.

## Запуск

В Windows:

```bat
run.bat --stage 1
```

В Linux или macOS:

```sh
chmod +x run.sh
./run.sh --stage 1
```

Конфигурацию можно указать параметром `--config путь/к/файлу.ini`.
Без `--stage` приложение последовательно выполняет все пять этапов.

## Конфигурация

Файл `config.ini` содержит секцию `[application]` и четыре обязательных
параметра:

| Параметр | Назначение |
| --- | --- |
| `package_name` | Имя анализируемого пакета |
| `source` | URL Git-репозитория или путь к тестовому описанию графа |
| `test_mode` | `true` включает локальный тестовый граф, `false` — URL |
| `output_file` | Имя итогового SVG-файла |

Этап 1:

```sh
./run.sh --stage 1
```

Приложение печатает каждую настройку в формате `ключ=значение`. Для
демонстрации ошибок измените по очереди имя пакета, источник, режим и
расширение выходного файла в `config.ini`.

## Этапы

1. INI-конфигурация и проверка пользовательских параметров.
2. Чтение прямых зависимостей из `Cargo.toml` по URL репозитория.
3. Обход графа зависимостей алгоритмом BFS и поддержка тестовых графов.
4. Порядок загрузки зависимостей и сравнение с `cargo tree`.
5. Экспорт диаграммы D2 и изображения SVG.

### Этап 2. Получение прямых зависимостей

Этап 2 клонирует URL и читает таблицы `[dependencies]` и
`[build-dependencies]` выбранного пакета. Учитываются зависимости из
таблиц целевой платформы и `[workspace.dependencies]`. Таблица
`[dev-dependencies]` исключена из графа загрузки.

```ini
[application]
package_name = serde
source = https://github.com/serde-rs/serde
test_mode = false
output_file = dependency-graph.svg
```

```sh
./run.sh --config config.ini --stage 2
```

## Проверка тестов

```sh
python -m unittest discover -s tests
```

### Этап 3. Транзитивный граф и тестовый режим

`--stage 3` обходит достижимые зависимости алгоритмом BFS без рекурсии.
Узел помечается посещённым при добавлении в очередь, поэтому цикл и общий
узел не приводят к повторному обходу.

В обычном режиме сначала читается `Cargo.lock`. Если lock-файла нет,
версии выбираются по публичному sparse index crates.io; `Cargo.toml` и
индекс разбираются стандартной библиотекой Python. Необязательные и
dev-зависимости в граф не включаются. Платформенные зависимости
учитываются без фильтра по текущей ОС, поэтому граф может включать
альтернативные ветви.

Локальные `path`-зависимости и зависимости из Git-репозиториев читаются
по их `Cargo.toml`. Для Git-источников выбирается заданный `branch`, `tag`
или `rev`, если он указан.

В тестовом режиме `source` указывает на файл рёбер. Например, для трёх
демонстрационных пакетов выполните:

```sh
./run.sh --config config.ini --stage 3
```

Перед запуском укажите в `config.ini` по очереди пары:
`ALPHA` / `tests/fixtures/alpha.graph`, `BETA` /
`tests/fixtures/beta.graph`, `GAMMA` / `tests/fixtures/gamma.graph`.
Сценарии показывают общий транзитивный узел, цикл и ромбовидную схему.

### Этап 4. Порядок загрузки и сравнение

Для ациклического графа используется топологический порядок
dependencies-first. Если есть цикл, приложение перечисляет узлы цикла и
не строит невозможный порядок. На тестовых графах сравнение с Cargo
пропускается: это специально заданные графы, а не проекты Cargo.

В обычном режиме приложение сравнивает рёбра и порядок с `cargo tree`
из установленного Rust toolchain. Эта команда используется только для
сравнения. Если версии или рёбра отличаются, выводятся размеры различий;
возможные причины — разрешение версий без lock-файла, включённые features
и платформенные зависимости. При отсутствии Cargo приложение явно
сообщает, что сравнение не выполнялось.

```sh
./run.sh --config config.ini --stage 4
```

### Этап 5. D2 и SVG

Приложение пишет текст диаграммы на языке D2 рядом с SVG-файлом. SVG
формируется средствами Python; отдельный рендерер не требуется. В узлах
сохраняются имена пакетов, рёбра направлены от пакета к зависимости.

```sh
./run.sh --config config.ini --stage 5
./run.sh --config configs/beta.ini --stage 5
./run.sh --config configs/gamma.ini --stage 5
```

Эти команды строят примеры для `ALPHA`, `BETA` и `GAMMA`. Каждый файл
конфигурации задаёт свой граф и имя выходного SVG. Выходные `.svg` и `.d2`
считаются генерируемыми файлами и исключены из Git.

Для реального Cargo-пакета граф сравнивается с рёбрами `cargo tree`.
Cargo выводит дерево в консоль, а приложение — ту же топологию в D2/SVG;
различия в рёбрах и порядке перечисляются в выводе этапа 5.
